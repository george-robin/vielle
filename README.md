# Vielle

**A Python guitar tablature generator with a reproducible dataset for future model experiments.**

Vielle converts chord progressions into aligned, six-string text tablature. As a guitar player, I started this project to connect a familiar musical task with learning software engineering and, eventually, language-model evaluation.

The current implementation uses predefined chord shapes and deterministic formatting. It includes input parsing, unit tests, and a dataset builder that keeps different text representations of the same progression together when splitting data.

**Status:** Generator, parser, and dataset builder implemented. Evaluation utilities started. MLX LoRA fine-tuning and retrieval-augmented question answering are planned.

## Example

```python
from src.input_parser import parse_progression
from src.generator import generate_progression_tab

chords = parse_progression("C G Am F")
print(generate_progression_tab(chords))
```

```text
   C           G           Am          F
e|-0-----------3-----------0-----------1----------|
B|-1-----------0-----------1-----------1----------|
G|-0-----------0-----------2-----------2----------|
D|-2-----------0-----------2-----------3----------|
A|-3-----------2-----------0-----------3----------|
E|-X-----------3-----------X-----------X----------|
```

Rows run from the high `e` string to the low `E` string in standard tuning. Numbers indicate frets, `0` indicates an open string, and `X` indicates a muted string. Horizontal spacing aligns chord shapes; it does not encode rhythm.

## Implemented features

- **Chord-to-tab generation:** Maps `C`, `A`, `G`, `E`, `D`, `F`, `Am`, `Dm`, and `Em` to fixed chord shapes, using consistent column widths across all six strings.
- **Flexible input parsing:** Accepts spaces, commas, and hyphens as separators, including mixed separators; normalizes capitalization and preserves chord order and repetitions.
- **Input validation:** The parser rejects empty, non-string, multiline, and unsupported-chord inputs. The generator requires at least two chords and rejects unknown chords.
- **Unit tests:** Eight pytest tests cover exact output for a reference progression, unsupported chords, the generator's minimum length, capitalization, and separator handling.
- **Reproducible data generation:** Produces input/output examples with a fixed random seed, split checks, and a manifest recording progression membership.

## Dataset design

The dataset contains **200 distinct chord progressions and 1,000 input/output records**. Each progression has five text variants: canonical, lowercase, compact, comma-separated, and space-separated.

| Split | Distinct progressions | Records |
| --- | ---: | ---: |
| Training | 140 | 700 |
| Validation | 30 | 150 |
| Test | 30 | 150 |

Progressions range from two to six chords. For each length, the builder selects 40 unique progressions and assigns 28 to training, six to validation, and six to testing.

**Splitting happens before text variants are generated.** This keeps alternate spellings of the same progression out of other splits. The builder also excludes the ten progressions reserved in `data/golden_tests.json`, checks split disjointness, and checks that the training split covers all supported chords.

The seed is fixed at `42`, and sampled progressions are sorted before shuffling. `data/split_manifest.json` records the seed, dataset version, counts, and progression IDs.

Targets are generated by the deterministic formatter. This is a small synthetic dataset for studying supported chord mappings and output formatting; it does not establish performance on arbitrary music or new chord types.

## Run locally

The project has been tested with Python 3.9.6 and pytest 8.4.2. The generator and dataset builder use the Python standard library.

```bash
git clone https://github.com/george-robin/vielle.git
cd vielle
python3 -m venv .venv
source .venv/bin/activate
python -m pip install pytest==8.4.2
```

On Windows, activate the environment with `.venv\Scripts\activate` instead.

Run a progression from the repository root:

```bash
python -c 'from src.input_parser import parse_progression; from src.generator import generate_progression_tab; print(generate_progression_tab(parse_progression("C G Am F")))'
```

Run the tests:

```bash
python -m pytest -q
```

The current suite contains eight tests. The ten reference fixtures in `data/golden_tests.json` are separate from that pytest count; the complete fixture collection is not yet wired into the test suite.

## Build the dataset

Generated dataset files are included in the repository. To generate them in a fresh working copy without those output files, run:

```bash
python -m data.build_dataset
```

The command writes:

- `data/dataset.jsonl`
- `data/val_set.jsonl`
- `data/test_set.jsonl`
- `data/split_manifest.json`

Each record contains its ID, progression ID, chord list, variant name, input text, and expected tab output. The builder uses exclusive file creation and will raise `FileExistsError` if an output already exists. Move all four existing outputs elsewhere before regenerating them.

## Current scope

Vielle supports one predefined voicing per supported chord in standard tuning. It does not transcribe audio, generate melodies, choose alternative voicings, or represent timing, strumming patterns, bends, or other expressive notation. The current interface is through Python functions; there is no web interface or dedicated CLI yet.
